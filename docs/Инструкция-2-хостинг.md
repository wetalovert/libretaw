# Инструкция 2. Хостить libretaw самому (VPS)

Сервер работает у хостинг-провайдера круглосуточно, с собственным адресом, автоматическими резервными копиями, управлением из приложения и, если хотите, поддержкой донатом.

Все данные **шифруются обязательно** (AES-256-GCM). Без парольной фразы шифрования хост не запускается.

Для домашнего сервера читайте **Инструкцию 1**.

## Что понадобится

- **VPS** с Ubuntu 22.04 или новее. Самого маленького тарифа (1 ГБ памяти) хватит для нескольких десятков человек.
- **Домен**, например `chat.example.com`, с A-записью на IP вашего VPS.
- **SSH-доступ** к серверу (логин и IP от провайдера).
- Три файла в одной папке: `libretaw-host.js`, `libretaw-server.js` и `libretaw.html`.

> **Быстрый путь.** Вариант А шага 6 выполняет шаги 2–5 автоматически одним скриптом. Шаги 2–5 нужны, если вы хотите делать всё вручную.

## Шаг 1. Подключитесь к серверу

```bash
ssh root@IP-ВАШЕГО-VPS
```

Дальше все команды выполняются на VPS.

## Шаг 2. Установите Node.js

```bash
apt update && apt upgrade -y
curl -fsSL https://deb.nodesource.com/setup_22.x | bash -
apt install -y nodejs
node -v
```

Нужна версия 18 или новее.

## Шаг 3. Отдельный пользователь и папка

```bash
useradd --system --home /opt/libretaw --shell /usr/sbin/nologin libretaw
mkdir -p /opt/libretaw
```

Загрузите файлы (с вашего компьютера):

```bash
scp libretaw-host.js libretaw-server.js libretaw.html root@IP-ВАШЕГО-VPS:/opt/libretaw/
```

На VPS выдайте папку пользователю:

```bash
chown -R libretaw:libretaw /opt/libretaw
```

## Шаг 4. Придумайте секреты и решите про пароль

Каждый длинный (лучше 20+ символов). Получить можно командой `openssl rand -base64 24`.

- **LIBRETAW_DATA_KEY** — парольная фраза шифрования данных. **Без неё данные не восстановить. Сохраните её в надёжном месте отдельно от сервера.**
- **ADMIN_TOKEN** — пароль администратора. Нужен только вам: для панели управления из приложения, резервных копий и доната.
- **LIBRETAW_TOKEN** — пароль подключения для всех пользователей. **Решите, нужен ли он.**

Правило для пользователей:
- Если задан `LIBRETAW_TOKEN` (или `DYNAMIC_PASSWORD=1`), пароль обязателен для всех. Приложение показывает «Пароль задан владельцем сервера. Он обязателен и из приложения не отключается». Вы не сможете отключить его из приложения: только сменить в службе и перезапустить.
- Если `LIBRETAW_TOKEN` не задан и одноразовые пароли выключены, подключение возможно без пароля. Приложение покажет «Владелец сервера пароль не задал: подключение без пароля». Так делают только для хоста внутри закрытой сети или за VPN (см. ниже).

## Шаг 5. Запустите хост как службу

Создайте `/etc/systemd/system/libretaw-host.service`:

```ini
[Unit]
Description=libretaw host
After=network.target

[Service]
User=libretaw
WorkingDirectory=/opt/libretaw
Environment=PORT=8080
Environment=HOST=127.0.0.1
Environment=LIBRETAW_DATA_KEY=ваша-фраза-шифрования
# Пароль подключения. Удалите эту строку, если хотите подключение без пароля.
Environment=LIBRETAW_TOKEN=ваш-пароль-для-всех
Environment=ADMIN_TOKEN=ваш-пароль-администратора
# Режим «только через VPN» (необязательно). Укажите сеть вашего VPN:
# Environment=VPN_ONLY=1
# Environment=VPN_NET=10.8.0.0/24
Environment=SERVER_NAME=Мой libretaw
Environment=TRUST_PROXY=1
Environment=BACKUP_HOURS=24
Environment=BACKUP_KEEP=7
ExecStart=/usr/bin/node libretaw-host.js
Restart=always

[Install]
WantedBy=multi-user.target
```

Подставьте свои значения. `HOST=127.0.0.1` означает, что хост слушает только внутри сервера, а снаружи его откроет прокси (шаг 6).

```bash
systemctl daemon-reload
systemctl enable --now libretaw-host
systemctl status libretaw-host
```

Проверка на сервере:

```bash
curl http://127.0.0.1:8080/host/health
```

Должно прийти `"ok":true`.

Проверка шифрования:

```bash
cd /opt/libretaw && sudo -u libretaw LIBRETAW_DATA_KEY=ваша-фраза node libretaw-host.js encrypt
```

Если данные уже зашифрованы, команда скажет «Зашифровано файлов: 0». Это нормально.

## Шаг 6. Адрес сервера: без домена или с доменом

Выберите один вариант.

### Вариант А. Без домена (быстрый старт)

Домен не нужен. Купите сервер, войдите по SSH и выполните:

Сначала загрузите папку `libretaw-src` на сервер (например, через `scp -r libretaw-src root@ВАШ_IP:/root/` с вашего компьютера), затем на сервере:

```bash
cd /root/libretaw-src/deploy/no-domain
sudo bash install.sh
```

Скрипт сам поставит Node.js, создаст службу `libretaw`, сгенерирует пароли и откроет порт 8080. В конце он покажет адрес для приложения вида `ws://ВАШ_IP:8080` и пароли. **Сохраните их сразу**: повторно они не выводятся (они лежат в `/etc/libretaw.env`, доступ только у root).

В приложении: **Режим работы → Хостинг**, адрес `ws://ВАШ_IP:8080`, пароль подключения из вывода скрипта.

Важно:
- Соединение без домена **не шифруется транспортным уровнем** (нет HTTPS). Сообщения шифруются самим приложением, но пароли подключения и метаданные (кто, когда и откуда подключается) идут по сети открыто.
- Веб-страница приложения, открытая по `https://`, не подключится к адресу `ws://` — браузер запрещает такие соединения. Открывайте приложение как файл `libretaw.html` (с компьютера) или установите приложение для Android или Linux.
- Для важного общения используйте VPN (WireGuard): поставьте его на сервер и на свои устройства, а в панели администратора включите режим «Только через VPN».

Проверка службы: `journalctl -u libretaw -n 20`. Остановить: `systemctl stop libretaw`.

### Вариант Б. С доменом (HTTPS через Traefik)

Нужен домен, A-запись которого указывает на сервер. Traefik сам получает и продлевает сертификат Let's Encrypt.

1. Установите Docker и Docker Compose по инструкции docs.docker.com/engine/install.
2. Скопируйте папку `deploy/traefik/` на сервер и перейдите в неё.
3. В `traefik.yml` замените `you@example.com` на свою почту.
4. В `dynamic.yml` замените `chat.example.com` на свой домен.
5. Создайте файл для сертификатов и закройте к нему доступ:

```bash
mkdir -p letsencrypt && touch letsencrypt/acme.json && chmod 600 letsencrypt/acme.json
```

6. Запустите Traefik: `docker compose up -d`.
7. Откройте порты (8080 наружу **не** открывать):

```bash
ufw allow OpenSSH
ufw allow 80
ufw allow 443
ufw enable
```

Проверка: `curl -sI https://chat.example.com/host/health` — ответ `HTTP/2 200`.

В приложении адрес: `wss://chat.example.com`.

Сервер libretaw при этом слушает только `127.0.0.1:8080`, поэтому снаружи он недоступен напрямую. Если вы сначала поставили вариант А, переключитесь на Б: в службе поменяйте `HOST=0.0.0.0` на `HOST=127.0.0.1` (файл `/etc/libretaw.env`), перезапустите службу и закройте порт 8080 (`ufw delete allow 8080/tcp`).

## Шаг 7. Подключите приложение

1. Откройте `https://chat.example.com/` (хост отдаёт приложение сам) или локальную копию `libretaw.html`.
2. **Настройки → Режим работы → Хостинг → Открыть «Хостинг».**
3. Адрес: `wss://chat.example.com`.
4. Пароль подключения: `LIBRETAW_TOKEN`, если владелец его задал. Если приложение пишет «Владелец сервера пароль не задал», поле можно оставить пустым.
5. Пароль администратора `ADMIN_TOKEN` вводите только вы.
6. Нажмите **Подключиться**.

## Панель администратора в приложении

Войдите паролем администратора (`ADMIN_TOKEN`). В панели:
- **Доступ.** Показывает, задан ли пароль подключения владельцем. Из приложения пароль, заданный при запуске, не меняется.
- **Только через VPN.** Переключатель, см. выше.
- **Одноразовые пароли.** Если включены, показывается текущий пароль и можно выпустить новый.
- **Резервные копии и донат.** Создание копий, восстановление, реквизиты (см. разделы ниже).

## Режим «Только через VPN»

Включить режим можно двумя способами.

**Способ 1. В службе.** Раскомментируйте в файле службы строки `VPN_ONLY=1` и `VPN_NET=...` (см. шаг 5), затем выполните `sudo systemctl daemon-reload && sudo systemctl restart libretaw-host`.

**Способ 2. Из приложения (нужен `ADMIN_TOKEN`).** Откройте **Настройки → Режим работы → Хостинг → Открыть «Хостинг»**, войдите паролем администратора. В панели найдите карточку **«Доступ к серверу»** и переключатель **«Только через VPN»** с полем для VPN-сети (например, `10.8.0.0/24`). При включении появится сообщение: «К этому хосту/серверу можно подключиться только через впн, включите пожалуйста впн».

Переменные службы имеют приоритет над настройкой в приложении при запуске.



В панели администратора (вкладка «Хостинг», нужен `ADMIN_TOKEN`) есть переключатель **«Только через VPN»** с полем для VPN-сети, например `10.8.0.0/24`. Хост принимает подключения только с адресов из этой сети. Остальным приложение покажет: «К этому хосту/серверу можно подключиться только через впн, включите пожалуйста впн». Подробнее в `docs/Режимы-доступа.md`.

Сеть проверяется по адресу подключения. Если хост стоит за обратным прокси Traefik (вариант Б шага 6), задайте `TRUST_PROXY=1` и настраивайте режим с учётом того, что адрес клиента должен попадать в сеть VPN. Режим не защищает от атаки изнутри самой VPN-сети.

## Резервные копии

- **Кнопкой** «Создать копию сейчас» в приложении (нужен пароль администратора).
- **Автоматически** каждые `BACKUP_HOURS` часов, хранятся последние `BACKUP_KEEP`.
- **Командой** на сервере:

```bash
cd /opt/libretaw
sudo -u libretaw LIBRETAW_DATA_KEY=ваша-фраза node libretaw-host.js backup
sudo -u libretaw LIBRETAW_DATA_KEY=ваша-фраза node libretaw-host.js list
```

Копии лежат в `/opt/libretaw/backups/`. Они зашифрованы тем же ключом.

**Важно:** копии лежат на том же диске, что и сервер. Копируйте папку `backups/` в другое место (другой сервер, облачное хранилище). Пример на ваш компьютер, по ключам SSH:

```bash
rsync -a /opt/libretaw/backups/ вы@ваш-компьютер:/home/вы/libretaw-backups/
```

### Восстановление

1. `systemctl stop libretaw-host`.
2. `sudo -u libretaw LIBRETAW_DATA_KEY=ваша-фраза node libretaw-host.js restore ИМЯ-КОПИИ`. Имя видно в `list`.
3. `systemctl start libretaw-host`.

Восстанавливать можно только при остановленном хосте. Восстановление требует ту же фразу шифрования, что и при создании копии.

## Поддержка донатом (необязательно)

Если хотите принимать добровольные пожертвования, добавьте реквизиты: криптокошелёк, карту, банковский счёт или что-то другое. Всё делается командами на сервере (`LIBRETAW_DATA_KEY` тот же):

```bash
cd /opt/libretaw
# посмотреть текущее состояние
sudo -u libretaw LIBRETAW_DATA_KEY=ваша-фраза node libretaw-host.js donate show
# добавить реквизиты: тип (crypto | card | bank | other), название, сами реквизиты
sudo -u libretaw LIBRETAW_DATA_KEY=ваша-фраза node libretaw-host.js donate add crypto BTC bc1qваш-адрес
sudo -u libretaw LIBRETAW_DATA_KEY=ваша-фраза node libretaw-host.js donate add card Карта 4276 0000 0000 0000
# включить показ пользователям
sudo -u libretaw LIBRETAW_DATA_KEY=ваша-фраза node libretaw-host.js donate on
# выключить показ (реквизиты сохраняются)
sudo -u libretaw LIBRETAW_DATA_KEY=ваша-фраза node libretaw-host.js donate off
# удалить все реквизиты
sudo -u libretaw LIBRETAW_DATA_KEY=ваша-фраза node libretaw-host.js donate clear
```

Или из приложения: в панели «Хостинг» (с паролем администратора) блок **«Поддержка донатом»** с переключателем, списком реквизитов и формой добавления.

Что видят пользователи: когда донат включён, у подключённых появляется блок «Поддержать проект» с вашими реквизитами и кнопкой «Копировать». Когда выключен, блока нет. Реквизиты хранятся зашифрованными, но показываются всем подключённым, пока донат включён. Добавляйте только то, что готовы публиковать.

Донат не обязателен: по умолчанию он выключен.

## Динамические пароли (по желанию)

Вместо постоянного пароля можно использовать одноразовые: каждый работает один раз, после входа сервер выдаёт новый. Включается переменной `DYNAMIC_PASSWORD=1` в службе или переключателем в панели администратора. Текущий пароль видно в панели, его можно скопировать и выпустить новый. Если задан постоянный `LIBRETAW_TOKEN`, он продолжает работать вместе с одноразовыми. Пароль при этом обязателен, как и при постоянном.

## Обновление

1. `systemctl stop libretaw-host`.
2. Замените `libretaw-host.js`, `libretaw-server.js` и `libretaw.html`. Папки `data/` и `backups/` не трогайте.
3. `systemctl start libretaw-host`.

Перед обновлением сделайте копию (`backup`).

## Безопасность

- Храните `LIBRETAW_DATA_KEY`, `LIBRETAW_TOKEN` и `ADMIN_TOKEN` в секрете. Потеря первого означает потерю данных.
- С доменом наружу открыт только HTTPS через Traefik, порт 8080 закрыт. Без домена порт 8080 открыт, поэтому пароли и данные подключения идут без шифрования на уровне сети: используйте VPN для важного общения.
- Оставляйте `TRUST_PROXY=1` только за прокси.
- Регулярно обновляйте систему: `apt update && apt upgrade`.
- Шифрование защищает данные на диске и сообщения в сети. Хост при этом знает, кто с кем переписывается по времени и объёму (метаданные), а сообщения групп и личные сообщения расшифровываются только на устройствах участников.

## Если что-то не работает

- Журнал: `journalctl -u libretaw-host -n 100 --no-pager`.
- Хост не запускается и пишет про парольную фразу: задайте `LIBRETAW_DATA_KEY` (не короче 12 символов).
- Хост пишет про неверную фразу: в службе указана не та фраза, которой создавались данные.
- `https://chat.example.com/host/health` не открывается: проверьте DNS, порты 80 и 443, статус прокси: `docker compose logs traefik` в папке `deploy/traefik`.
- Приложение не подключается: адрес начинается с `wss://`, пароль совпадает с `LIBRETAW_TOKEN`.
