# libretaw: свой сервер

> **Не путайте с хостингом.** «Свой сервер» (этот файл) работает у вас дома или на вашем компьютере. Если хотите держать сервер у хостинг-провайдера с резервными копиями и управлением из приложения, используйте `libretaw-host.js` и «Инструкцию 2» (`Инструкция-2-хостинг.md`).

`libretaw-server.js` — небольшая программа без зависимостей (нужен только Node.js 18+). Вы запускаете её у себя, все ваши устройства подключаются к ней, и сообщения идут через неё.

Сервер пересылает личные чаты, группы, каналы, реакции, опросы, голоса в опросах, истории и общую комнату. Он **хранит сообщения для тех, кто не в сети** (до 7 дней) и вложения: фото, видео, голосовые, кружки, стикеры (до 14 дней). Данные остаются у вас.

## Быстрый старт

1. Положите `libretaw-server.js` и `libretaw.html` в одну папку.
2. Запустите:

```bash
LIBRETAW_TOKEN=мой-секретный-пароль node libretaw-server.js
```

Windows (PowerShell):

```powershell
$env:LIBRETAW_TOKEN="мой-секретный-пароль"; node libretaw-server.js
```

3. Откройте `http://адрес-сервера:8080` — сервер сам отдаёт приложение. Пароль обязательно задайте: обычный (`LIBRETAW_TOKEN`) или динамический (см. ниже).
4. В приложении: **Настройки → Режим работы → Свой сервер**, затем появившаяся внизу вкладка **Сервер**. Введите адрес (`192.168.1.10:8080` или `wss://chat.example.com`) и пароль, нажмите «Подключиться».

> Версия приложения на claude.ai не может подключаться к чужим серверам (так устроена её защита). Открывайте приложение с вашего сервера или из локальной копии файла.

## Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `PORT` | `8080` | порт |
| `HOST` | `0.0.0.0` | адрес прослушивания |
| `LIBRETAW_TOKEN` | пусто | обычный (постоянный) пароль сервера |
| `DYNAMIC_PASSWORD` | выкл. | `1` включает динамический (одноразовый) пароль |
| `OTP_LENGTH` | `8` | длина одноразового пароля (6–16 символов) |
| `OTP_TTL_MIN` | `0` | менять неиспользованный пароль каждые N минут (0 = не менять) |
| `ADMIN_TOKEN` | пусто | пароль администратора (управление паролями из приложения) |
| `MAX_FAILS` | `5` | неверных паролей до блокировки IP на 10 минут |
| `TRUST_PROXY` | выкл. | `1`: брать IP клиента из `X-Forwarded-For` (за обратным прокси) |
| `SERVER_NAME` | `libretaw server` | название для клиентов |
| `MOTD` | пусто | приветствие |
| `DATA_DIR` | `./data` | очереди и вложения |
| `APP_FILE` | `./libretaw.html` | файл приложения для адреса `/` |
| `BLOB_TOTAL_MB` | `1024` | лимит хранилища вложений |
| `TLS_CERT`, `TLS_KEY` | — | пути к сертификату и ключу (включают `https`/`wss`) |

## Динамический (одноразовый) пароль

Дополнительная защита, которую можно включить или выключить в любой момент. **Обычный пароль (`LIBRETAW_TOKEN`) продолжает работать**: динамический пароль действует вместе с ним, а не вместо него.

### Как это работает

1. Сервер выдаёт одноразовый пароль, например `K7QX-M2PD`.
2. Первый человек вводит его в приложении (в то же поле пароля). Пароль **сразу становится недействительным**, а сервер создаёт новый для следующего человека.
3. Следующий человек вводит новый пароль, после чего снова создаётся новый, и так по кругу. Один пароль нельзя использовать дважды.

Устройство, добавленное по одноразовому паролю, сервер запоминает по секретному ключу устройства. При следующих подключениях пароль уже не нужен (приложение само стирает использованный пароль из настроек). Чтобы закрыть доступ устройству, отзовите его.

### Включить

```bash
DYNAMIC_PASSWORD=1 LIBRETAW_TOKEN=обычный-пароль node libretaw-server.js
```

Обычный пароль можно не задавать: тогда войти можно только по одноразовому. Текущий одноразовый пароль:

- выводится в консоль при запуске и после каждого использования;
- хранится в файле `data/current-password.txt` (права 600);
- виден в приложении администратору (см. ниже).

### Управление из приложения

Задайте `ADMIN_TOKEN=пароль-администратора`. После подключения на вкладке **«Сервер»** появится блок **«Администрирование»**. Введите пароль администратора, и вы сможете:

- увидеть текущий одноразовый пароль и скопировать его;
- выпустить новый пароль вручную;
- включить или выключить динамический пароль «на лету» (состояние сохраняется в `data/state.json` и при следующем запуске сильнее переменной окружения);
- посмотреть устройства на сервере и **отозвать** любое из них.

Первое подключение администратор делает по обычному паролю или по одноразовому из консоли.

### Защита от подбора

- Пять неверных паролей с одного IP блокируют его на 10 минут, даже если после этого ввести правильный (`MAX_FAILS`).
- Если набирается 10 неверных попыток, одноразовый пароль сразу меняется.
- Пароль состоит из букв и цифр без похожих символов (`0/O`, `1/I`), регистр не важен, дефис необязателен.
- Проверка паролей выполняется за постоянное время.

### Что важно знать

- Выключение динамического пароля **не отключает** уже добавленные устройства: чтобы закрыть им доступ, отзовите их.
- Неверный пароль администратора тоже считается неудачной попыткой.
- За обратным прокси задайте `TRUST_PROXY=1`, иначе блокировка будет работать по адресу прокси.

## Доступ из интернета

Нужен безопасный адрес `wss://`. Проще всего поставить перед сервером обратный прокси, например Caddy:

```
chat.example.com {
  reverse_proxy localhost:8080
}
```

Лучше всего вообще не открывать порт в интернет, а держать сервер внутри своего VPN (WireGuard или Headscale).

## Автозапуск

systemd (`/etc/systemd/system/libretaw.service`):

```ini
[Unit]
Description=libretaw server
After=network.target

[Service]
WorkingDirectory=/opt/libretaw
Environment=LIBRETAW_TOKEN=мой-секретный-пароль
ExecStart=/usr/bin/node libretaw-server.js
Restart=always

[Install]
WantedBy=multi-user.target
```

Docker:

```bash
docker run -d --name libretaw --restart=always -p 8080:8080 \
  -v /opt/libretaw:/app -w /app \
  -e LIBRETAW_TOKEN=мой-секретный-пароль \
  node:22-alpine node libretaw-server.js
```

## Что хранит сервер

Папка `data/`:

- `state.json` — идентификаторы пользователей, состав групп и каналов, очереди недоставленного;
- `blobs/` — вложения.

Копируйте её для резервной копии. Сообщения в очереди и вложения лежат на сервере в открытом виде: сервер видит содержимое. Держите его у себя и под своим контролем. Сквозное шифрование запланировано отдельно.

## Защита

- обычный пароль сервера и (по желанию) динамические одноразовые пароли с блокировкой подбора;
- при первом подключении ID привязывается к секретному ключу устройства (чужой ID занять нельзя; ключ хранится в аккаунте и переезжает с ним);
- отправитель проверяется сервером, подделать его нельзя;
- лимиты: размер сообщения (8 МБ), вложения (30 МБ), 40 событий в секунду;
- проверка имён файлов вложений (обход папок невозможен).

## Протокол (кратко)

WebSocket по адресу `/ws`, текстовые JSON-кадры.

| Кадр | Направление | Описание |
|---|---|---|
| `{k:'hello', id, sec, n, token, gs, cs}` | клиент → сервер | вход (`token` — обычный или одноразовый пароль); `gs`/`cs` — ID ваших групп и каналов |
| `{k:'welcome', name, motd, users, up, queue, adm, via}` | сервер → клиент | ответ на вход; `via`: `token`, `otp` или `enrolled`; `adm`: включено ли администрирование |
| `{k:'presence', users:[{id,n}]}` | сервер → клиент | кто в сети |
| `{k:'ev', mid, d}` | клиент → сервер | событие (сообщение, реакция, голос в опросе…) |
| `{k:'ev', mid, d, ttl, src}` | сервер → клиент | событие с проверенным отправителем |
| `{k:'put', id, i, n, t, d}` | клиент → сервер | загрузка вложения по частям |
| `{k:'mreq', id}` → `{k:'mch', id, i, n, t, d}` | клиент ↔ сервер | скачивание вложения |
| `{k:'err', m, o}` | сервер → клиент | `auth` (`o`: включён ли динамический пароль), `ban`, `id`, `hello`, `quota`, `revoked` |
| `{k:'admin', t, a, v?, id?}` | клиент → сервер | администрирование: `a` = `status`, `rotate`, `dyn`, `revoke` |
| `{k:'admin', ok, dyn, otp, users, ...}` | сервер → клиент | состояние для администратора |

## Если не подключается

Проверьте адрес и порт, пароль, что сервер запущен (`/health` отвечает `ok`), что порт открыт на файрволе и что для адреса из интернета используется `wss://`. Ошибка пароля, блокировка по IP или занятый ID показываются на вкладке «Сервер».

## Отложенное удаление сообщений

В любом чате (личном, группе, канале, общем чате) можно удалить своё сообщение через заданное время: **Удалить через…** (1 минута, 5 минут, 1 час, 1 день, 1 неделя) или сразу. Пока время не наступило, в строке сообщения показан значок 🗑 и оставшееся время. Удаление можно отменить: «Отменить удаление».

- Удаление идёт тем же путём, что и реакции: только участникам этого чата. Сервер не передаёт его остальным пользователям.
- Сервер проверяет отправителя, поэтому удалить чужое сообщение нельзя.
- Каждая новая версия решения (назначить удаление, отменить) перекрывает прежнюю, поэтому старая отмена не отменит новое удаление.
- Удаление происходит на каждом устройстве по его часам, поэтому расхождение в минуту-две возможно при разных часах.
- Сообщение, которое удалено у получателя, остаётся у отправителя, пока не наступит его срок.

## Отложенная отправка

Сообщение можно запланировать: удержите кнопку отправки (или выберите «Позже» в окне вложения), укажите время (5 минут, 1 час, завтра в 9:00 или своё). Запланированное сообщение видно только вам, в чате оно показано пунктиром с временем отправки. Нажмите на него, чтобы отменить.

- Пока время не наступило, сообщение **не передаётся** ни серверу, ни собеседникам.
- Отправка работает в любом чате, где вы можете писать (с теми же правами, что и обычно).
- Расписание хранится на вашем устройстве. Если приложение закрыто в назначенное время, сообщение уйдёт при следующем открытии.

## Архив чатов

Любой чат (личный, группа, канал) можно перенести в архив кнопкой в шапке чата, а вернуть той же кнопкой. В списке чатов появляется строка «Архив» с количеством.

- Архив хранится на вашем устройстве и не виден собеседникам.
- **Скрывать архив** (Настройки → Приватность): архивные чаты исчезают из списка, из «Люди» и из ленты. Открыть архив можно только через «Открыть скрытый архив». Если задан PIN-код, он будет запрошен.
- Архив не даёт полной защиты: уведомления о новых сообщениях в архивном чате могут всплыть, а сами сообщения хранятся на устройстве как обычно.

## Уведомления

Настройки: **Настройки → Уведомления**.

- **Уведомления.** Главный переключатель.
- **Звук.** Короткий сигнал при входящем сообщении (нужно, чтобы браузер разрешил звук на странице).
- **Показывать текст.** Выключено: вместо текста «Новое сообщение», а заголовок «libretaw» без имени чата.
- **Откуда уведомлять.** Личные чаты, группы, каналы, служебные уведомления (входы и события безопасности), каждое отдельно.
- **Тихие часы.** В выбранный промежуток уведомления не показываются. Промежуток может идти через полночь (например, с 23:00 до 07:00).
- **Колокольчик в шапке чата.** Выключает уведомления только для этого чата.

Системные уведомления браузера требуют разрешения: кнопка «Разрешить системные уведомления». Если разрешения нет, уведомления показываются внутри приложения. Уведомления не приходят для открытого чата, если страница видна, и для чатов в скрытом архиве.

## Данные и память

Настройки → **Данные и память**: сколько места занимает libretaw (сообщения, фото и файлы, настройки), сколько занимает браузер для этого сайта, и отдельно по каждому чату.

- **Пересчитать** обновляет цифры.
- **Очистить** у чата удаляет его историю (системные сообщения остаются) и освобождает файлы этого чата. Нажмите дважды, чтобы подтвердить.
- **Удалить неиспользуемые файлы** убирает файлы, на которые не ссылается ни один чат, стикер, реакция или отложенное сообщение.
- **Удалить все фото, видео и файлы из чатов** убирает вложения из всех чатов; текст сообщений и стикеры остаются. Действие касается только этого устройства.

## Динамический цвет

Кастомизация → **Динамический цвет**. Браузер не может читать обои устройства, поэтому вы выбираете файл с обоями (из галереи или файлов). libretaw берёт из него самый яркий цвет как основной, второй как дополнительный и подстраивает насыщенность тем. Чтобы вернуться к обычной теме, нажмите «Выключить динамический цвет».

## Кто может мне писать

Настройки → Приватность → **Кто может мне писать**:

- **Все.** Любой, кто знает ваш ID, может написать первым.
- **Контакты.** Писать первым могут только те, с кем у вас уже есть личный чат.
- **Никто.** Личные сообщения, реакции, голоса в опросах, удаления и файлы от людей не принимаются ни в каком чате. Группы и каналы работают как обычно.

Это правило проверяет приложение на вашем устройстве. Сервер хранит сообщения для вас до 7 дней, даже если вы ограничили приём, потому что сервер не знает ваших настроек. Сами сообщения отбрасываются на устройстве и не показываются.

**Как собеседник узнаёт про «Никто».** Когда вы меняете этот пункт и когда ваше устройство (клиент) снова подключается, оно отправляет собеседникам служебное уведомление с вашей настройкой. Если у собеседника выбрано «Никто», вместо поля ввода у него появляется надпись «Пользователь запретил писать». Служебное уведомление не показывается в переписке.

## Списки

В любом чате (личном, группе, канале) нажмите скрепку → **Список**: назовите список и добавьте пункты (до 50). Любой участник чата может отметить пункт выполненным, и отметка сразу видна остальным: кто и когда её поставил. Повторное нажатие снимает отметку.

- Отметки передаются тем же путём, что и реакции: только участникам чата, сервер проверяет отправителя.
- Если две отметки на один пункт пришли в разное время, побеждает более поздняя.
- Списки сохраняются и в файлах режима «По файлу» вместе с отметками.

## Расшифровка голосовых

Включается в **Настройки → Приватность → Расшифровка голосовых**.

- Текст собирается во время записи голосового сообщения, и вы видите его под записью вместе с отправленным сообщением. Собеседник получает тот же текст.
- Распознавание работает через встроенное в браузер распознавание речи: в **Chrome и Edge** (звук при этом отправляется сервисам Google), в Firefox и Safari не поддерживается.
- Расшифровать уже записанные голосовые, которые были записаны без этой функции, нельзя: браузер умеет распознавать только живую речь.
- Язык распознавания — русский.

## Музыка профиля

**Профиль → Музыка профиля → Добавить музыку.** Выберите аудиофайл (mp3, m4a, ogg, wav, flac, aac, opus; до 15 МБ). Один трек на профиль, его можно заменить или удалить.

**Кому видна (Настройки → Приватность → Кому видна музыка профиля):**
- **Всем.** Трек получают все, кто онлайн и подключён к вам (через сервер, локальную сеть или VPN).
- **Контактам.** Только люди, с которыми у вас есть личный чат.
- **Никто.** Трек не передаётся никому; тем, кто его уже получил, он убирается.

Трек слушают в разделе «Люди» (кнопка ▶ у контакта). Сам файл передаётся по тому же пути, что и фото: его можно получить, когда владелец трека в сети, либо если клиент загрузил его на сервер. Трек хранится на устройстве в базе браузера; при очистке «неиспользуемых файлов» он не удаляется. Ограничение: у людей вне сети, которых нет в контактах, трек появится только когда они снова будут онлайн.

## Папки чатов

**Папки.** Кастомизация → **Папки чатов**. Создайте папку, укажите название и отметьте чаты (личные, группы, каналы). Папки появляются в строке фильтров над списком чатов после «Все», в том порядке, в котором вы их расставили. Порядок меняется кнопками ↑ и ↓. Папку можно переименовать, изменить её чаты или удалить. Чаты в папках остаются на своих местах и не переносятся: папка только показывает выбранные чаты.

Папки хранятся только на вашем устройстве и собеседникам не видны.

## Профиль: комментарии и система

**Комментарии.** Люди → **Профиль** у контакта: там можно оставить комментарий к его профилю (до 300 символов). Комментарий приходит только владельцу профиля: он видит их в **Профиль → Комментарии ко мне** и может удалить. Ваш профиль в списке комментариев других не показывается.

**Настройки → Приватность:**
- **Кто может комментировать мой профиль:** Все / Контакты / Никто.
- **Кому видно, с какой ОС я сижу:** Всем / Контактам / Никто. Пункт в профиле показывает систему и браузер, на которых вы сейчас работаете. Собеседники видят его в своём профиле у вас.

Правила проверяются и на вашем устройстве, и на устройстве отправителя. «Контакты» означают людей, с которыми у вас есть личный чат. Информация о профиле передаётся контактам напрямую; «Всем» распространяется только на тех, кто онлайн.

## Комментарии к постам канала

**Владелец** включает и выключает комментарии в **Канал → Информация → Комментарии к постам**. Когда включено, подписчики могут комментировать каждый пост: под постом появляется кнопка «💬 Комментировать» (или число комментариев). Владелец может удалить любой комментарий. Если комментарии выключены, новые не принимаются, а старые остаются видны.

- Комментарии передаются только подписчикам канала, по тому же пути, что и посты: через сервер, локальную сеть или VPN.
- Сервер проверяет отправителя, поэтому комментарий нельзя отправить от чужого имени.
- Подписчики видят переключатель владельца и узнают его из постов канала.
- Комментарии хранятся на устройствах и в файлы режима «По файлу» не входят.

## Подписи постов канала

Владелец включает подписи в **Канал → Информация → Подписи постов**. Когда подписи включены, под каждым постом владельца или администратора пишется его имя: «— Имя». Подписи видят все подписчики.

- Включать и выключать подписи может **только владелец**. Подписчики и администраторы этого сделать не могут: их устройства принимают настройку только от владельца.
- Подпись ставится на посты, опубликованные после включения. Старые посты не меняются.

## Сохранение адреса и пароля

В **Свой сервер → Сервер** есть переключатель **«Сохранять адрес и пароль»**.

- **Включено** (по умолчанию): адрес и пароль запоминаются на устройстве, и при следующем открытии приложение подключается само (если включено автоподключение). Вводить их заново не нужно.
- **Выключено:** адрес и пароль не записываются на устройство. Сразу после выключения сохранённые значения удаляются из хранилища. После перезапуска приложения их придётся ввести снова.

Данные хранятся в браузере на этом устройстве, в открытом виде. Не включайте сохранение на чужом компьютере.

## Список сохранённых серверов

В **Свой сервер → Сервер** можно сохранить несколько серверов. Введите адрес и пароль, при желании дайте название и нажмите **«Сохранить сервер в список»**.

- **Выбрать** переключает приложение на этот сервер и сразу подключает к нему. Текущий сервер отмечен точкой.
- **Удалить** убирает сервер из списка (сам сервер не затрагивается).
- Список сохраняется на устройстве, пока включён переключатель «Сохранять адрес и пароль». Если он выключен, список не записывается и после перезапуска пустой.

## Шифрование

**Данные на диске шифруются всегда.** Сервер не запускается без парольной фразы `LIBRETAW_DATA_KEY` (не короче 12 символов). Все файлы состояния, вложений и паролей шифруются AES-256-GCM. Команды: `node libretaw-server.js check` (проверить), `node libretaw-server.js encrypt` (зашифровать старые открытые данные).

**Что шифруется сквозным шифрованием (ключи только у участников):**
- текст личных сообщений;
- реакции, голосование в опросах, удаление сообщений и отложенное удаление в личных чатах;
- комментарии к профилю.

**Как это устроено.** При первом запуске каждое устройство создаёт свою пару ключей (ECDH, P-256). Публичный ключ передаётся собеседникам при подключении (локальная сеть, сервер) и в карточке контакта. Сообщение шифруется AES-256-GCM с ключом, который получается из общего секрета двух устройств. Сервер и посредники (mesh) видят только адресата и шифротекст. Ключ устройства хранится в браузере; при переносе аккаунта на другое устройство ключ переносится вместе с файлом аккаунта.

**Что пока не шифруется:**
- групповые чаты (см. раздел «Шифрование групп» ниже);
- каналы (пока не шифруются);
- фото, видео, файлы и голосовые (их содержимое передаётся без дополнительного шифрования, а на своём сервере хранится как есть);
- файлы режима «По файлу» (шифруются только если задан пароль файла);
- описание профиля, ОС, музыка и оформление профиля (видны контактам согласно настройкам приватности).

**Проверка ключей.** В **Настройки → Приватность** показан отпечаток вашего ключа. Сравните его с отпечатком собеседника другим способом (лично или другим мессенджером), чтобы убедиться, что ключ настоящий. Пока сравнения нет, первый обмен ключами доверяет серверу.

**Если собеседник не передал ключ** (старая версия), сообщение уходит без шифрования. Если ключ собеседника уже известен, незашифрованное сообщение от него отбрасывается.

## Динамические пароли в хостинге

Панель **Хостинг** (с паролем администратора) показывает блок «Динамические пароли»: переключатель, текущий одноразовый пароль, кнопки «Скопировать» и «Новый пароль». Одноразовый пароль работает один раз, после входа сервер сразу выдаёт новый. Обычный пароль сервера продолжает работать.

## Шифрование групп

Групповые сообщения, реакции, опросы, удаления, списки и голоса в группе шифруются общим ключом группы (AES-256-GCM).

- Ключ создаёт тот, кто первым отправил сообщение в группу (владелец или первый участник). Он передаётся каждому участнику в личном зашифрованном сообщении, поэтому его не видит сервер и посредники.
- Новый участник, у которого нет ключа, запрашивает его у участников группы, сообщения ждут ключ и открываются, когда он придёт.
- Если участника удалили, владелец меняет ключ: удалённый не сможет читать сообщения, отправленные после этого. Удалить его ID должен быть известен: он определяется по его сообщениям в группе, поэтому участник должен написать в группу хотя бы раз.
- Список участников сервер отдаёт только участникам группы.

Ограничения: старые сообщения удалённый участник уже видел, их не перешифровывают. Ключ группы хранится на устройствах участников. Проверка подлинности ключей пока не добавлена: как и в личных чатах, первый обмен доверяет серверу.
