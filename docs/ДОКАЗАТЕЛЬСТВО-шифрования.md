## 2. Что лежит на диске сервера

Все файлы данных начинаются с признака `LTWE` (AES-256-GCM). Содержимое открыть без парольной фразы нельзя.

```
state.json: 4c 54 57 45 09 24 87 49 6b b3 4a 67 12 6b ce 8d ...   (LTWE + iv + tag + шифротекст)
```

Поиск открытых слов по всей папке данных сервера: `ГРУППОВОЙ-СЕКРЕТ-1` — 0 файлов, `ОТВЕТ-БОБА` — 0, `ПОСЛЕ-УДАЛЕНИЯ-3` — 0.

Реквизиты доната на диске тоже зашифрованы: проверка `donatetest` выполняет поиск адреса кошелька в `state.json` и получает 0 совпадений.

## 3. Контрольная проверка (поиск работает)

Тот же поиск по файлу с открытым текстом находит слово в 1 файле. Значит, отсутствие совпадений в пунктах 1 и 2 — результат шифрования, а не ошибка поиска.

## 4. Сервер без ключа или с неверным ключом не работает

- Без `LIBRETAW_DATA_KEY` сервер не запускается: «Нужна парольная фраза для шифрования данных».
- С открытыми данными на диске сервер не запускается и просит выполнить `encrypt`.
- С неверным ключом сервер не открывает данные: «Неверная LIBRETAW_DATA_KEY».
- Команда `encrypt` зашифровывает старые открытые данные: «Зашифровано файлов: 1», после неё файл начинается с `LTWE`.

## 5. Личные сообщения, реакции, группы

Проверки на настоящем хост-процессе:
- `e2eint` — личные сообщения и реакции: расшифровываются у получателя, в сыром трафике открытого текста нет, подделка без шифрования отбрасывается (9 из 9).
- `groupint` — групповой ключ: передача участникам, открытый текст в трафике отсутствует, удалённый участник после смены ключа не читает новые сообщения (10 из 10).
- `donatetest` — донат: реквизиты показываются только при включении и хранятся зашифрованными (5 из 5).

## Как повторить

```bash
# 1. Групповой сценарий с настоящим хостом (пишет кадры в /tmp/proof/wire.txt)
node groupint.js

# 2. Личный сценарий
node e2eint.js

# 3. Поиск открытого текста на диске (подставьте папку из groupint: /tmp/proof/root.txt)
grep -rl "ГРУППОВОЙ-СЕКРЕТ-1" "$(cat /tmp/proof/root.txt)"    # ничего не должно вывести

# 4. Признак шифрования файла состояния
head -c 4 "$(cat /tmp/proof/root.txt)/d/state.json"            # LTWE
```

Важно: тесты работают на одном компьютере с несколькими процессами, а не на разных устройствах в сети. Для полной уверенности повторите их на своих устройствах и своём хосте.
